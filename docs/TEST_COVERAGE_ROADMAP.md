**优先提升的模块**:

1. **`src/commands`** (45.58% → 75%+)
   - 命令解析和执行

   - 边界条件

2. **`src/sandbox`** (53.48% → 75%+)
   - 超时处理

   - 清理逻辑

3. **`src/tools/shared.ts`** (54.4% → 80%+)
   - 路径验证逻辑

**预计提升**: +6-8%

5. **`src/closed-loop`** (51.62% → 75%+)
   - 验证管道
   - 反馈注入

6. **`src/database`** (68.32% → 80%+)
   - 备份管理

**预计提升**: +4-6%

## 🚫 不追求的目标

以下情况**不需要达到高覆盖率**：

1. **纯类型文件** (`types.ts`, `*.d.ts`) - 0% 是正常的
2. **CLI 交互工具** (`setup-wizard.ts`) - 难以自动化，手动测试即可
3. **实验性功能** (`src/experimental/`) - 快速迭代中
4. **简单导出** (`index.ts`) - 导出声明无需测试

## 🔧 技术手段

### 测试工具

- **Vitest** - 已配置，运行快速
- **@vitest/coverage-v8** - 覆盖率报告
- **Vitest UI** - 可视化调试

### 覆盖率报告

```bash
# 生成 HTML 报告
npm run test:coverage

# 查看报告
open coverage/index.html  # macOS
start coverage/index.html # Windows
```

### CI 集成

当前 CI 已运行测试，下一步：

```yaml
# .github/workflows/test.yml
- name: Check coverage threshold
  run: |
    npm run test:coverage
    # 设置最低阈值
    npx vitest --coverage --coverage.lines=80
```

## 💡 最佳实践

1. **测试金字塔**: 
   - 70% 单元测试
   - 20% 集成测试
   - 10% E2E 测试

2. **优先测试**:
   - 安全相关代码 (100%)
   - 核心业务逻辑 (90%+)
   - 工具函数 (80%+)
   - UI/CLI 交互 (50%+)

3. **避免过度测试**:
   - 不为 getter/setter 写测试
   - 不测试第三方库
   - 不追求 100% 覆盖率
