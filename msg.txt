feat(config): add env registry covering all 61 variables, with drift guard

The existing src/config/index.ts claimed to be "unified configuration that
replaces scattered process.env access". It declared 25 names of which 5 were
simply wrong - CODEYANG_WATCH_MODE, CODEYANG_PLANNER_ENABLED and
CODEYANG_REFLEXION_ENABLED do not exist; the agent reads CODEYANG_WATCH,
CODEYANG_PLANNER and CODEYANG_REFLEXION. It covered 15 of the 61 variables
actually read across 27 files, and `--help` listed 8.

Added:
- src/config/env.ts       registry: name, kind, category, description,
                          default, choices, secret flag - for all 61 vars
- src/config/envReader.ts typed getters (envString/Int/Float/Bool/List/Secret)
                          that reject unknown names, enforce choices, and
                          throw on malformed numbers instead of silently
                          defaulting
- src/config/envHelp.ts   --help section generated from the registry, grouped
                          by category, so help text cannot drift again

envBool deliberately parses true/1/yes/on and false/0/no/off rather than using
Boolean(process.env.X), which treats the string "false" as truthy - the reason
CODEYANG_AUTO_VERIFY=false did not actually disable verification.

Fixed the 3 wrong names in src/config/index.ts.

Added src/config/env-drift.test.ts, which scans src/ for process.env reads and
fails when a variable is read but not declared, or declared but never read.
It caught 4 variables I had missed while building the registry. That test is
the actual deliverable here - the registry will rot without it.

Verified: `node dist/index.js --help` now prints all 61 variables.
Suite: 2841 passing / 7 skipped / 0 failing (was 2796). tsc and eslint clean.
